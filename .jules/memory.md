- When registering Consul services in Nomad job templates (`provider = "consul"`), explicitly setting `address = "${attr.unique.network.ip-address}"` in `service` stanzas ensures Consul receives the node's network IP address for service health checks.
- Nomad job deployments (like `pipecatapp`) should include a pre-deploy and verify step as a unit test integrated directly into `bootstrap.sh` prior to finalizing the deployment.
- The `ansible/roles/pam_u2f` role enforces hardware User Presence (UP) via `libpam-u2f` for `sudo` and SSH access, accepting `enable_pam_u2f` (default `false`), `pam_u2f_auth_file`, `pam_u2f_origin`, `pam_u2f_appid`, and `nouserok` options.
- External agent multi-factor authentication is handled by `TOTPTool` (`pipecatapp/tools/totp_tool.py`), which generates 6-digit RFC 6238 TOTP codes by fetching secret seeds from Consul KV (`v1/kv/totp/<service>`), environment variables (`TOTP_SEED_<SERVICE>`), or direct inputs, with built-in standard library fallback when `pyotp` is unavailable.
- To reliably run the test suite (e.g., `tests/unit/`), first install development dependencies by running `uv pip install -r requirements-dev.txt`, then execute tests via `uv run pytest <test_path>`.
- Application-level or tool-level fixes MUST NEVER modify cluster substrate ports, bypass TLS certificates, or reconfigure Nomad/Consul service blocks based on the Hierarchy of Stability. Fixed Infrastructure Ports: Consul (8500), Nomad (4646), IPFS Gateway (8092), IPFS API (5001), Pipecat App (8007).
- In Nomad, Consul service registration and ACL authentication tokens are managed at the agent level (`server.hcl` / `client.hcl`) under the top-level `consul { ... }` block; placing `consul { token = ... }` stanzas inside a Nomad job or group specification is invalid HCL syntax.
- In `bootstrap.sh`, dependency installations (`npm install` and `pip install`) are cached using `.npm_checksum` and `.pip_checksum` hash files and checked against binary/directory existence. Passing `--reinstall-deps` or `--force` overrides the cache. `./bootstrap.sh --status` uses a lightweight setup (`ensure_status_environment`) to perform read-only status checks without running heavy dependency installations.
- In `pipecatapp/tools/__init__.py`, all newly added agent tools must be registered in both `__all__` and `_module_lookup` to enable dynamic lazy module loading.
- The KeylessWebResearcherTool (`pipecatapp/tools/keyless_web_researcher_tool.py`) uses the `duckduckgo-search` library to provide a keyless HTML web search fallback when primary web search APIs are unavailable or rate-limited.
- Infrastructure health checks (`/health` and `/api/status`) must be restricted to local loopback access (`127.0.0.1`, `localhost`, or `Host` header matching) to prevent exposing cluster topology and status over the wider Headscale mesh network.
- The deployment topology utilizes a 'Brain vs. Body' inversion. A high-memory APU (e.g., Strix Halo) acts as the central control and primary inference node ('Brain'), while legacy low-resource nodes (e.g., Core 2 Duo) handle periphery tasks like sensors, IPFS storage, builds, and control plane daemons ('Body').
- Consul ACL policy files (e.g. HCL policy definitions) must be stored in a dedicated subdirectory like `{{ consul_config_dir }}/policies/` rather than directly under `{{ consul_config_dir }}`, to prevent 'consul validate' and the Consul agent daemon from misinterpreting ACL policy syntax as agent configuration.
- `MemoryCandidateTool` (`pipecatapp/tools/memory_candidate_tool.py`) manages the memory candidate promotion pipeline (`emit`, `list_pending`, `promote`, `reject`) backed by the `memory_candidates` SQLite staging table in `PMMMemoryBackend` (`pipecatapp/memory_backends_impl/pmm_backend.py`).
- To test the `pipecatapp.tool_server` module using `fastapi.testclient.TestClient`, ensure environment variables like `TOOL_SERVER_API_KEY` are set before importing the `app` instance to prevent API validation errors during initialization.
- When running `scripts/ci_ansible_check.sh`, the script executes playbooks in check mode (`--check`), which skips starting services (like Nomad or Consul). This leads to false-positive failures in downstream tasks depending on those services. Avoid aggressively modifying tasks with `ignore_errors: yes` or `when: not ansible_check_mode` solely to pass this script.
- When deploying models on unified memory APUs (like a 64GB Strix Halo), always enforce strict memory guardrails (e.g., `--ctx-size` caps, `cgroup` limits) to leave approximately 15-25GB of system RAM unclaimed. Failing to cap memory will starve the OS and cause `zram` thrash or OOM-kills.
- `ProcessInvestigatorTool` (`pipecatapp/tools/process_investigator_tool.py`) provides process inspection and profiling capabilities (`py_spy`, `gdb_py_bt`, `strace`, `perf`, `list_processes`), accessible programmatically as an agent tool or via CLI through `scripts/troubleshoot.py process` and `scripts/cluster_ctl.sh process`.
- When running local ROCm simulations via `act` for `.github/workflows/test-cluster.yml`, create dummy devices on the host (`sudo mknod /dev/kfd c 1 3`, `sudo mkdir -p /dev/dri`, `sudo mknod /dev/dri/card0 c 226 0`, `sudo mknod /dev/dri/renderD128 c 226 128`) to prevent container startup failures due to missing `--device` mappings.
- When completing a task from the TODO list, always manually update the TODO list file to mark the item as complete and validate the fix or implementation with a corresponding test.
- Both `FileEditorTool` (`pipecatapp/tools/file_editor_tool.py`) and `ASTEditorTool` (`pipecatapp/tools/ast_editor_tool.py`) support preflight verification (including connected `repository_tests` coverage) via `CodeGraphTool` when `verify_preflight` is set to `True`.
- The `HybridModelRouter` (`pipecatapp/workflow/routing_and_delegation.py`) evaluates profile and routing definitions in `pipecatapp/config/adaptive_hybrid_model_routing.yaml`, dispatching queries to primary local vLLM/llama.cpp endpoints and cascading to cloud fallbacks on error.
- When Ansible executes tasks using an unprivileged `become_user` (such as `pipecatapp`) with `system_tmpdirs = /var/tmp/pipecat_build`, ensure `/var/tmp/pipecat_build` exists with mode `1777` prior to running unprivileged tasks so module payloads can be read and executed without permission errors.
- When formulating an execution plan using the `set_plan` tool, the final pre-commit step must be exactly the string: 'Complete pre-commit steps to ensure proper testing, verification, review, and reflection are done.' Do not append numbers, bullets, or extra formatting to this string.
- `HermesTool` (`pipecatapp/tools/hermes_tool.py`) provides a dedicated interface enabling swarm agents to dispatch tasks or execute commands via external Hermes Agents and run HPC actions inside Singularity/Apptainer container sandboxes.
- When formatting or linting Markdown files, use `npx markdownlint-cli --fix <file>`. Exercise caution if using `djlint --reformat` on Markdown files, as `djlint` can strip necessary blank lines around headings and list elements, causing `markdownlint` validation failures.
- To prevent `ImportError` during pytest execution in `tests/unit/test_mcp_servers.py`, ensure the `mcp` package is constrained to version `<2` (e.g., via `uv pip install 'mcp<2'`) when running tests, as versions >= 2.0 introduce breaking incompatibilities.
- The `auto-merge.yml` workflow requires any pull request to be accompanied by a new issue definition in the `ISSUES/` directory to merge automatically.
- When adding a new tool to be invoked via the tool server, it must be registered in `pipecatapp/agent_factory.py` (within `TOOL_CLASS_MAP` and `REMOTE_SUPPORTED_TOOLS` or `HEAVY_TOOLS`) and safely imported in `pipecatapp/tool_server.py` using `_safe_import_and_init`.
- The architecture follows an 'Agent-as-Ledger-Clerk' and 'Fuzzy Proposes, Deterministic Disposes' pattern. Agents act as fuzzy semantic routers proposing changes, but every commit must pass a deterministic verification gate (e.g., build, tests, `git apply --check`) before writing to an underlying REA (Resource/Event/Agent) ledger.
- The `WorktreeDelegationManager` (`pipecatapp/workflow/routing_and_delegation.py`) provisions isolated Git worktrees under `.worktrees/` for subagents, enforces tool restrictions, and collects git diff patches and execution summaries.
- Workflow nodes (such as `PostProcessorNode`) must never use dynamic `eval()` or `exec()` on untrusted input; templating should use `jinja2.sandbox.SandboxedEnvironment` and complex execution must be delegated out-of-process to the isolated `tool_server`.
- `CodeGraphTool` (`pipecatapp/tools/code_graph_tool.py`) provides AST-based structural code analysis actions (`blast_radius`, `preflight`, `repository_trace`, `repository_tests`) and is registered in `pipecatapp/tools/__init__.py` and mapped dynamically in `pipecatapp/agent_factory.py` under `TOOL_CLASS_MAP`.
- The `ansible/roles/ipmi_fan_control` role manages bare-metal system fan control and telemetry, running `asrock_ipmi_fan_control.py` as a systemd service with support for multiple drivers (`asrock_ipmi`, `supermicro_ipmi`, `dell_ipmi`, `sysfs_pwm`, `auto`), writing Prometheus metrics to `/var/lib/telegraf/ipmi_fan_metrics.prom` for Telegraf ingestion.
- Google Takeout archive ingestion is managed on-demand via `scripts/import_takeout.sh` (deployed to `/usr/local/bin/import_takeout.sh`), which unpacks archives into `/mnt/takeout-hoard` (`openclaw_takeout_mount_dir`). `openclaw_enable_takeout` is set to `false` by default in `ansible/roles/openclaw/defaults/main.yml`.
- In the `nomad` Ansible role, host volume mount paths (such as `openclaw_takeout_mount_dir` and `openclaw_workspace_dir`) must be created via directory tasks prior to Nomad agent startup and parameterized in `defaults/main.yaml` and Nomad `.hcl.j2` templates to prevent volume validation failures.
- The Apptainer/Singularity sandbox executor (`ApptainerSandboxExecutor` in `pipecatapp.tools.code_runner_tool` and `ansible/roles/tool_server/tools/code_runner_tool.py`) enables unprivileged HPC execution via `apptainer exec` / `singularity exec` with bind paths, workspace mounting, and security capability drops when `SANDBOX_EXECUTOR` is configured to `singularity` or `apptainer`.
- The `VisualWorkflowDAG` (`pipecatapp/workflow/visual_dag_engine.py`) tracks workflow nodes and communication edges via `MessageEnvelope` packets, supporting DAG execution and export to Mermaid (`to_mermaid()`) and React Flow JSON (`to_reactflow_json()`) formats.
- In `pipecatapp`, the `TwinService` orchestrator triggers its core conversational workflow logic only on `TranscriptionFrame`s. When simulating user input in tests or benchmarks, wrap text in `pipecat.frames.frames.TranscriptionFrame(text=user_input, user_id="...", timestamp="0")` rather than using `TextFrame`, which will be passively forwarded.
- The `tap_orchestrator` service (`services/tap_orchestrator/`) processes physical proximity challenge verification and RF signal presence telemetry (via `/api/v1/telemetry/rf`), logging spatial presence facts to the Datalog REA ledger and synchronizing device/room weights in Consul KV.
- Always use `uv` for Python environments and dependency management (e.g., `uv pip install`, `uv run --no-sync python -m pytest`). Use `uvx` for ephemeral CLI tools (e.g., `uvx ansible-lint`, `uvx --from ansible-core ansible-playbook`).
- SEAL loop self-modifying agents must gate every commit through deterministic checks. Destructive operations or actions involving exfiltration must remain strictly human-in-the-loop.
- The vLLM service (`vllm-main`, `vllm-server`, `vllm`) is prioritized in Consul service discovery across `pipecatapp` workflow nodes (`discover_main_llm_service`, `SimpleLLMNode`) and `scripts/healer.py` for high-performance GPU/APU inference.
